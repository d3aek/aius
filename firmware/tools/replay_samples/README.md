# DTS replay sample pack

This directory contains a reproducible generator for replay-manager inputs. It
does not ship copyrighted television or film audio. The generated material is
synthetic, but deliberately exercises the same channel roles a 5.1 programme
mix uses:

- `channel_id_51` has a different steady tone on FL, FR, C, LFE, SL and SR.
- `channel_impulse_51` puts a transient in each channel at a different time.
- `cinematic_program_51` combines a changing centre speech proxy, a stereo
  front bed, low-frequency effects, and quieter surround ambience.

Each generated item has a WAV reference, raw DTS Core (`.dts`), and IEC 61937
S/PDIF stream (`.iec`) suitable for the Aius replay manager. The `.iec` output
is produced by FFmpeg's `spdif` muxer and is the file to upload to the device.

Generate the default 30-second pack with:

```sh
./generate.sh
```

Upload one IEC replay, resuming an interrupted `.part` upload automatically:

```sh
./upload.sh --device http://192.0.2.66 --token TOKEN \
  --id cinematic_program_51 generated/cinematic_program_51.iec
```

Use `OUT=/path/to/output DURATION=60 ./generate.sh` for a longer pack. The
generator requires an FFmpeg build with the `dca` encoder; Aius' checked-in
10 ms DTS and IEC vectors remain available when FFmpeg is not installed.

The DTS encoder is experimental in FFmpeg, so generated bytes can differ
between FFmpeg versions. Validate the resulting `.iec` file with `ffprobe`
before uploading it.

## Channel identity

**Every `join` in the generator states `map=` explicitly, and it must.** Without
it `join` guesses the input-to-output assignment by channel name; each mono
`aevalsrc` declares layout `mono`, whose single channel is named FC, so all six
inputs claim FC and the guess rotates the front three — input 0 lands on FC,
input 1 on FL, input 2 on FR — leaving LFE and the surrounds alone. Nothing
errors, every channel is present, and only a per-channel tone identity check
sees it.

Packs generated before 2026-07-28 carry that rotation. `channel_id_51` is the
hardware bench tone programme, so the rotated pack is what produced defect 30 in
[`aius-network-hardening.md`](../../../docs/plans/aius-network-hardening.md) — a
decoded capture with FR's tone in the left output, which reads as a decoder
channel permutation and was in fact the source material. **Regenerate and
re-upload any pack older than that date**; the firmware needs no change.
