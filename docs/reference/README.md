# Aius reference

Current-state descriptions of what the Aius carrier and its `teensy41-optical`
firmware actually are. These documents record results and cite the code, schematic
inputs, or measurements behind them, so a claim can be re-checked rather than
trusted. Future work lives in [`../plans/`](../plans/); bench procedures live in
[`../guides/`](../guides/).

## Firmware

- **[Aius audio signal path](signal-path.md)** — every stage from the optical
  receiver to the S/PDIF transmit register: the implementing module and function,
  buffers and their memory bank, arithmetic domain, and share of the per-block
  time budget. Reach for it before changing anything in the audio chain; the
  audio-quality roadmap in `../plans/aius-dsp-config-api.md` updates this document
  in the commit that ships each change.
- **[Aius firmware I/O reference](firmware-io.md)** — every I/O operation the
  image performs, the buffers it owns, the bank each occupies, and the argument
  that none can disturb the audio path. Reach for it when adding I/O or spending
  memory; it is the companion to `signal-path.md` and states the result of
  `../plans/aius-network-hardening.md`.
- **[Aius user interface](user-interface.md)** — the four SD-hosted pages (DSP
  editor, device status, replay manager, firmware upgrade), with screenshots,
  the routes each reads and writes, and how the interface is served. Reach for
  it to see what the device looks like in use without having one. Screenshots
  live in `images/` and are rendered from the committed page assets against
  stubbed responses, not captured from a live device.
- **[AIUS USB application control protocol](usb-control-protocol.md)** — the
  line-oriented ASCII protocol on the Teensy USB virtual serial port
  (`/dev/ttyACM*`): transport limits, requests, responses, error vocabulary.
  Reach for it when driving or scripting the device over USB. It excludes the
  RawHID capability transport, the Ethernet HTTP API, and HalfKay.

## Hardware

- **[Aius functional topology](functional-topology.md)** — operating modes,
  blocks, data/control/power flows, clock domains, DMA buffers and latency
  boundaries, with stable contract ids. Reach for it for the ids other hardware
  documents cite, and for what each mode does today where a name has been
  outgrown.
- **[Aius interfaces and states](interfaces-and-states.md)** — connectors,
  controls, power domains, operating states, fault scenarios and transitions:
  the FMEA contract that schematic capture works from.
- **[Aius board floorplan](board-floorplan.md)** — a concept placement of the
  carrier inside the Hammond 1455N1201BK enclosure, showing where every
  connector, module and support IC sits. It is a placement concept, not a routed
  board and not manufacturing data.

`board-floorplan.svg` is generated by [`board-floorplan.py`](board-floorplan.py)
from `interfaces-and-states.md`, `functional-topology.md`, and
`../../evidence/design/provisional-components.csv`. Edit the script, not the SVG.

## Bench and measurement

- **[CM6206 playback corruption characterization](cm6206-playback-corruption.md)** —
  the verified byte-lane corruption model for the CM6206 loop adapter, its
  evidence table, what it excludes, and the quarantine fingerprint. Reach for it
  when a capture shows isolated one-frame impulses or when judging whether a
  measurement adapter is trustworthy.
- **[Aius project scale](project-scale.md)** — the measured size of the
  `src/hardware/aius` subtree with the exact command behind each figure, pinned
  to a commit. Reach for it for a citable number; re-run the commands for a
  current one.
