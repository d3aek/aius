# Aius reference

Current-state descriptions of the Aius carrier and its `teensy41-optical`
firmware. These record results and cite the code, schematic inputs or
measurements behind them, so a claim can be re-checked. Future work lives in
[`../plans/`](../plans/); bench procedures in [`../guides/`](../guides/).

## Firmware

- **[Aius audio signal path](signal-path.md)**: every stage from the optical
  receiver to the S/PDIF transmit register: the implementing module and function,
  buffers and their memory bank, arithmetic domain, and share of the per-block
  time budget. Read it before changing anything in the audio chain. The
  audio-quality roadmap in [`aius-dsp-config-api.md`](../plans/aius-dsp-config-api.md)
  updates it in the commit that ships each change.
- **[Aius firmware I/O reference](firmware-io.md)**: every I/O operation the
  image performs, the buffers it owns, the bank each occupies, and the argument
  that none can disturb the audio path. The companion to
  [`signal-path.md`](signal-path.md) when adding I/O or spending memory, and the
  result of [`aius-network-hardening.md`](../plans/aius-network-hardening.md).
- **[Aius user interface](user-interface.md)**: the four SD-hosted pages (DSP
  editor, device status, replay manager, firmware upgrade), with screenshots,
  the routes each reads and writes, and how the interface is served. Screenshots
  live in [`images/`](images/) and are live captures from the deployed board,
  driven by a real 5.1 source.
- **[AIUS USB application control protocol](usb-control-protocol.md)**: the
  line-oriented ASCII protocol on the Teensy USB virtual serial port
  (`/dev/ttyACM*`): transport limits, requests, responses and error vocabulary,
  for driving or scripting the device over USB. It excludes the RawHID
  capability transport, the Ethernet HTTP API, and HalfKay.

## Hardware

- **[Aius functional topology](functional-topology.md)**: operating modes,
  blocks, data/control/power flows, clock domains, DMA buffers and latency
  boundaries. Source of the stable contract ids other hardware documents cite,
  and of what each mode does today where a name has been outgrown.
- **[Aius interfaces and states](interfaces-and-states.md)**: connectors,
  controls, power domains, operating states, fault scenarios and transitions:
  the FMEA contract that schematic capture works from.
- **[Aius board floorplan](board-floorplan.md)**: a concept placement of the
  carrier inside the Hammond 1455N1201BK enclosure, showing where every
  connector, module and support IC sits. A placement concept, not a routed board
  and not manufacturing data.

[`board-floorplan.svg`](board-floorplan.svg) is generated by
[`board-floorplan.py`](board-floorplan.py) from
[`interfaces-and-states.md`](interfaces-and-states.md),
[`functional-topology.md`](functional-topology.md) and
[`provisional-components.csv`](../../evidence/design/provisional-components.csv).
Edit the script, not the SVG.

## Bench and measurement

- **[CM6206 playback corruption characterization](cm6206-playback-corruption.md)**:
  the verified byte-lane corruption model for the CM6206 loop adapter, its
  evidence table, what it excludes, and the quarantine fingerprint. Consult it
  when a capture shows isolated one-frame impulses, or when judging whether a
  measurement adapter is trustworthy.
- **[Aius project scale](project-scale.md)**: the measured size of the Aius
  subtree as one current snapshot (code, docs, tests, churn, defects, per-day
  commit history and agent cost), with the exact command behind each figure,
  pinned to a commit. Cite it for a figure; re-run the commands for a current one.
